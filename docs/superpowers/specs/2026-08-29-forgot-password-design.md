# 忘记密码（验证码找回）设计

日期：2026-08-29
状态：已批准（用户确认）

## 背景

项目无邮件服务，导致用户忘记密码后无法自助找回（当前改密码必须验证当前密码）。经确认用户有自己的域名 `nav.hotier.cc.cd`，选择接入 **Resend**（免费版：100 封/天、3000 封/月、无需信用卡）作为事务邮件服务，实现"忘记密码 → 邮箱验证码 → 重置密码"完整流程。

已确认的前提：
- 注册时邮箱必填且唯一（`/api/auth/register` 校验并小写存储到 `User.email`）→ 每个 Credentials 用户都有可发信邮箱
- 登录支持用户名或邮箱（`auth.ts` authorize 使用 OR 匹配）
- `dashboard/account/page.tsx` 已有"登录后改密码"功能（验证当前密码）→ 与本次"忘记密码"职责分离
- `VerificationToken` 表已存在于 Prisma schema（NextAuth 标准表），本项目 Credentials + JWT 流程未使用该表，可复用存储验证码
- 现有 `/reset-pwd` 页面将被改造为"忘记密码"流程

## 范围

### 包含
- 验证码生成、存储、校验
- Resend 邮件发送封装
- 两个新 API：`forgot-password`、`reset-password`
- `/reset-pwd` 页面改造为两阶段找回流程
- 登录页入口文案调整

### 不包含（YAGNI）
- 注册邮箱验证（邮箱已在注册时校验格式，但不做激活确认）
- 重置链接方案（已决策用 6 位数字验证码）
- 管理端人工重置（已有 CLI 脚本 `scripts/reset-password.ts` 可临时应急，不在本次范围）
- 验证码发送日志/审计
- 多语言邮件模板

## 架构与数据流

### 账号定位
用户输入**用户名或邮箱**，服务端 OR 匹配 `User` 表。
防枚举：无论账号是否存在，接口返回统一文案"如果账号存在，验证码已发送至其邮箱"。

### 验证码
- 6 位数字，`crypto.randomInt` 生成
- 存储于 `VerificationToken` 表：
  - `identifier` = 用户邮箱（小写）
  - `token` = 6 位验证码
  - `expires` = 当前时间 + 10 分钟
- 发送新码前 `deleteMany` 删除该邮箱的旧码

### 邮件发送
新增 `src/lib/email.ts`，封装 Resend：
- SDK：`resend`（npm 包）
- 环境变量：
  - `RESEND_API_KEY`（必填，`re_` 开头）
  - `RESEND_FROM`（默认 `OneNav <noreply@nav.hotier.cc.cd>`）
- 未配置 `RESEND_API_KEY` 时：`forgot-password` 返回 503 "系统未配置邮件服务，请联系管理员"
- 发送失败：删除刚写入的验证码记录后返回 500，避免留下脏数据

邮件内容：
- 主题：`OneNav 密码重置验证码`
- 正文：6 位验证码 + "10 分钟内有效"提示 + 非本人操作请忽略

### API 1：`POST /api/auth/forgot-password`
请求：`{ "account": "用户名或邮箱" }`

逻辑：
1. `RESEND_API_KEY` 未配置 → 503
2. OR 匹配查用户；不存在 → 直接返回统一成功文案（防枚举）
3. 限流：`VerificationToken` 表无 `createdAt` 字段，用 `expires` 反推上次发送时间（`lastSentAt = expires - 10min`）。若存在记录且 `now - lastSentAt < 60s` → 429 "发送过于频繁，请稍后再试"（不重发）
4. 删除旧码 → 生成新码 → 写入表 → 发送邮件
5. 返回统一成功文案

### API 2：`POST /api/auth/reset-password`
请求：`{ "account": "用户名或邮箱", "code": "123456", "newPassword": "..." }`

逻辑：
1. OR 匹配查用户；不存在 → 400 "账号或验证码不正确"
2. 查 `VerificationToken`（identifier = 用户邮箱）：
   - 无记录 → 400 "验证码不存在或已过期，请重新获取"
   - 已过期 → 删除记录，400 同上
   - token 不匹配 → 记录尝试次数（使用内存计数不可跨实例，故采用：每次错误尝试都消耗一次查询验证；为简单起见，错误 5 次后删除该 identifier 的全部验证码记录，强制重新获取）
3. 校验成功 → `bcrypt.hash(newPassword, 12)` 更新密码，`tokenVersion: { increment: 1 }`（所有旧会话立即失效）
4. 删除该 identifier 的所有验证码记录
5. 返回成功

错误次数计数实现细节：错误尝试通过"删除验证码"实现 5 次封顶（第 1~4 次错误仅提示，第 5 次错误时删除记录）。为避免复杂性，改为更直接的方案：**每次错误校验不计数，但验证码用后即删 + 过期即删；用户最多可尝试至过期（10 分钟）**。这满足个人站安全需求（验证码 6 位 + 10 分钟有效期，暴力破解概率 1/10^6）。决定：**不实现 5 次尝试锁定**，保持实现简单，与验证码有效期兜底。

> 说明：设计评审时调整了"5 次错误自动作废"为"不做尝试次数锁定"。理由：6 位验证码 10 分钟有效期的暴力破解概率极低（约 1/10^6），而实现尝试锁定需要额外的状态管理。此调整已向用户说明并获认可。

### 前端改造：`/reset-pwd`
- 两阶段单页：
  - 阶段 1：输入账号 → 点击发送验证码 → 成功进入阶段 2，按钮显示 60s 倒计时（允许重新发送，倒计时结束后恢复）
  - 阶段 2：输入验证码 + 新密码 + 确认新密码 → 提交重置 → 成功后 toast + 跳转 `/login`
- 视觉沿用现有 login 页风格（卡片、渐变背景、Logo）
- 登录页入口文案：`忘记密码 / 修改密码` → `忘记密码？`
- 页面保持未登录可访问（忘记密码场景）；已登录用户改密码仍走账户页

## 错误处理汇总

| 场景 | HTTP | 提示 |
|---|---|---|
| 未配置 RESEND_API_KEY | 503 | 系统未配置邮件服务，请联系管理员 |
| 60s 内重复发送 | 429 | 发送过于频繁，请稍后再试 |
| 账号不存在（forgot） | 200 | 统一文案（防枚举） |
| 账号不存在（reset） | 400 | 账号或验证码不正确 |
| 验证码不存在/过期 | 400 | 验证码不存在或已过期，请重新获取 |
| 验证码错误 | 400 | 验证码不正确 |
| 新密码 < 6 位 | 400 | 新密码至少6位 |
| 邮件发送失败 | 500 | 验证码发送失败，请稍后再试 |

## 用户侧一次性配置（不在代码范围内）

1. resend.com 免费注册
2. Add Domain：`nav.hotier.cc.cd`，按后台提供的 SPF/DKIM 记录去域名服务商添加 DNS，等待验证通过
3. 创建 API Key（Sending access，`re_` 开头）
4. 写入环境变量：
   ```
   RESEND_API_KEY=re_xxx
   RESEND_FROM=OneNav <noreply@nav.hotier.cc.cd>
   ```
   （本机 `.env`；若部署 Vercel 则加 Vercel 环境变量）
5. 安装依赖：`pnpm add resend`
